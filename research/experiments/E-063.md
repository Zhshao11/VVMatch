# E-063 - M055 DeformDesc Matcher-Consumption Alignment

Created: 2026-09-06
Method: `M055/v0.1`
Working name: `DeformDesc Matcher-Consumption Alignment`
Status: `AUTHORIZED_FOR_ENGINEERING / frozen method intent`

## 1. Purpose

The next visible-visible route is not another small gate on the old SLiM
trunk. It is a DeformDesc-centered feature extractor that tries to make the
unchanged OfficialSLiM matcher consume the feature interface correctly while
keeping DeformDesc's stronger local discrimination.

The hypothesis is that the current failure mode is interface mismatch, not a
lack of feature signal. D0 anchors a clean DeformDesc long-final baseline.
D1 adds matcher-facing projection/calibration. D2 adds matcher-survival loss
so correct points survive the frozen downstream chain.

HPatches is evaluation only. It must not be used for training, checkpoint
selection, threshold selection, image-size selection, pair-list selection, or
method selection.

## 2. Parent Evidence And Boundary

Motivation:

- E-059 showed long feature-side interface shaping helps MRR but not enough to
  overtake the same-run OfficialSLiM interface consumption bundle.
- E-060A/E-061 showed multiple short feature-side shapers can move MRR and
  mutual, but not enough to clear the promotion gate.
- E-062 showed the DeformDesc structural branch is the clearest structural
  candidate, and the DeformDesc row was reload-clean, but the formal r4 batch
  was invalid for promotion because the runner's reference resolution was wrong
  and three variants failed checkpoint reload tolerance.
- E-041 and the old receiver/matcher routes are not this experiment: they
  either remove the official downstream path or move the action point too late.

Archive matching check must include E-041, E-045A/B/C/D/E, E-058, E-059,
E-060A, E-061, E-062, receiver/matcher routes E-055/E-056/E-057,
PairQPA/APQ/SetRank, learned PROSAC, pointwise Sampson/top-k, and
post-processing gates.

E-063 is materially different from E-062 because the action point is now a
DeformDesc-centered matcher-consumption route with explicit projection and
survival objectives, not a structural sweep of independent feature variants.

## 3. Frozen Interface

```text
raw visible image pair
-> DeformDesc-centered ASCS feature extractor with optional projection/
   calibration/survival blocks
-> unchanged OfficialSLiM matcher/fine/dual-softmax/quota/RRU/RANSAC path
-> frozen MegaDepth interface diagnostics
-> optional HPatches endpoint diagnostic only after a frozen endpoint
```

Untouched invariants:

- OfficialSLiM matcher, fine matching, dual-softmax, quota, RRU, RANSAC,
  materialization, and evaluator stay frozen.
- OfficialSLiM-O0 is inference-only baseline/ruler and is not trained.
- No HPatches training or HPatches-based method/checkpoint/threshold/image-size
  selection.
- No SourceMux, bl_tunnel, SAR/OSDataset, heldout1200, Gate2/test/final/
  protected reads, artifact deletion/overwrite, learned quota, RRU redesign,
  direct logit/selected-ID edit, or post-final scorer.

## 4. Tracks

- `D0_DeformDesc_LongCleanFinal`: DeformDesc branch only, with the cleanest
  long-final training budget. This is the anchor baseline for the new route.
- `D1_DeformDesc_ProjectionCalibration`: add feature-side projection,
  normalization, temperature, and confidence calibration to match the frozen
  official matcher's input distribution.
- `D2_DeformDesc_SurvivalLoss`: add an explicit survival loss so correct points
  survive the frozen downstream chain:
  descriptor topK -> mutual -> dual-softmax -> quota -> RRU.

The three tracks are independent single-GPU trajectories from the same declared
parent checkpoint. Do not warm-start D1/D2 from D0 unless the contract is
explicitly amended.

## 5. Training Protocol

Training data:

- MegaDepth outdoor train only, matching the SLiM/E-059 recovered training
  protocol as closely as available on zzvr.
- Preserve physical-scene train/validation/test isolation and scene ID leading
  zeros.
- Do not train on HPatches.

Budgets:

- Preflight: unit tests, identity/no-op, positive control, activation/action
  audit, optimizer/gradient/update audit, checkpoint reload, and tiny-set
  forced overfit.
- `D0`: predeclared long endpoint, preferred `38 x 4800` or exact equivalent
  exposure if resources permit.
- `D1` and `D2`: short endpoints `4800`, `9600`, and `19200` optimizer steps.
- If a short track beats the gate at `19200`, still keep the frozen long-run
  plan separate; do not silently convert it into the final route.

Routing:

- Check `zzvr` first and use watchdog.
- Run tracks in parallel as independent single-GPU jobs on idle `zzvr` GPUs.
- Do not silently convert a single trajectory into DDP.

## 6. Losses And Diagnostics

`D0`:

- Deformable-descriptor reliability/discriminativeness loss
- Descriptor-geometry regularization
- Local-window rank/mutual diagnostics

`D1`:

- `D0` losses plus projection normalization
- score-spread and saturation band losses
- confidence calibration
- top1-top2 / top1-topk gap calibration

`D2`:

- `D1` losses plus survival loss through the frozen official chain
- mutual retention
- dual-softmax retention
- quota retention
- RRU-facing rank survival

Primary decision metrics:

- `strict_top10`, MRR, mutual/cycle, score spread, saturation, collision/tie
  diagnostics, and descriptor norm distribution.
- Top1-top2 and top1-topk gap distributions.
- Survival table rows for descriptor topK, mutual, dual-softmax, quota, and
  RRU.
- Final AUC, inlier ratio, match count, and RANSAC inliers if endpoint
  evaluation is run.
- Action-path delta reaching selected IDs or RRU-facing tensors through the
  unchanged official path.
- Matched controls must degrade.
- Wall-clock time, GPU model/id, memory, feature-forward latency, parameters,
  precision, optimizer steps, and processed windows.

References:

- `E059-M051-SameStep` at `4800`, `9600`, and `19200`.
- Best E-060A/E-061 rows at `19200`.
- `E062` DeformDesc diagnostic row.
- Frozen `ASCS-OfficialMatcher` parent.
- Untouched inference-only `OfficialSLiM-O0` as external ruler.

## 7. Gates

Gate0 implementation fidelity:

- Function contract frozen with runner before GPU execution.
- Archive matching check and source/config/checkpoint hash locks pass.
- Identity/no-op reproduces the declared parent path within tolerance.
- Positive control changes the matcher-consumed rank/distribution and reaches
  selected IDs or RRU-facing tensors through the unchanged official path.
- Activation, gradients, optimizer membership, parameter deltas, checkpoint
  reload, and action-path audits pass.
- Forbidden-read audit clean.

Gate1 short-training adequacy:

- Tiny-set overfit passes before formal short training.
- Every completed track logs optimizer steps, processed windows, full metric
  trajectory, final-window slopes, wall-clock time, GPU id/model, precision,
  effective batch, and memory.

Gate2 early route promise:

- At `19200` steps, `D1` or `D2` must keep MRR no worse than `-0.005`
  absolute versus `E059-M051-SameStep` while improving `strict_top10` or
  mutual/cycle by at least `+0.02` absolute on allowed MegaDepth validation
  diagnostics.
- It must beat the best E-060A/E-061 row on at least one of `strict_top10` or
  mutual/cycle without losing more than `0.005` MRR.
- Score spread and saturation must remain in the SLiM-consumable band.
- Matched controls must degrade.

Gate3 promotion readiness:

- A passing single track may be promoted to a separately frozen long MegaDepth
  training experiment with optional HPatches endpoint replay.
- If no track passes Gate2, E-063 rejects only the exact M055 implementation
  and placement, not the broader DeformDesc or feature-extractor direction.

## 8. What E-063 Can And Cannot Reject

Can reject:

  seed, and short or long training recipe under unchanged OfficialSLiM matcher
  compatibility.

Cannot reject:

- DeformDesc feature extractors broadly.
- Feature-side interface shaping broadly.
- Independent matcher design.
- Learned quota.
- RRU redesign.
- HPatches endpoint behavior.
